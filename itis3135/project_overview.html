Page Design Requirements

Each page below utilizes a consistent header and a navigation bar for single-click access.

1. Home Page (index.html)

  • Purpose: To introduce Hivemind Entertainment and provide a look at current Roblox projects.
  • Audience: General public, players, and potential partners.
  • Content: Studio welcome statement, a latest release image slider section, page descriptions, and social media links.
  • Data Entry: No.
  • Validations: None.
  • Interactions: Navigation links, social media buttons, and image slider controls.
  • Actions: Clicking navigation links redirects to other pages; social media buttons open to external links; slider buttons cycle through game environment images.
  • Special Notes: None.

2. Projects Gallery (projects.html)

  • Purpose: A filterable catalog of all studio games.
  • Audience: Players looking for games and recruiters looking at the studio portfolio.
  • Content: High-quality thumbnails and game descriptions.
  • Data Entry: Yes, search bar and category filters.
  • Validations: Basic text length validation and character sanitization for the search input.
  • Interactions: Search text field, genre filter buttons (drop-down), and game links.
  • Actions: Typing in search or selecting a genre triggers an AJAX request to filter results dynamically without a page refresh; clicking a game link navigates to the external game location.
  • Special Notes: None.

3. About Us (about.html)

  • Purpose: Share the studio's history and team background.
  • Audience: Potential partners and the community.
  • Content: Timeline of studio milestones, core values, and technical specifications.
  • Data Entry: No.
  • Validations: None.
  • Interactions: jQuery-UI Accordion headers and internal anchor links.
  • Actions: Clicking accordion headers expands or collapses sections to reveal detailed history or specification data.
  • Special Notes: None.

4. Developer Blog (blog.html)

  • Purpose: To provide updates on development progress and studio news.
  • Audience: Dedicated fans and community members.
  • Content: Chronological posts with text and embedded media.
  • Data Entry: Yes; Newsletter subscription form.
  • Validations: Email format validation to ensure a valid address is entered.
  • Interactions: Subscription text field, submit button, and a "Back to Top" button.
  • Actions: Clicking submit processes the email for the newsletter (simulated); clicking "Back to Top" scrolls the view to the header.
  • Special Notes: Uses embedded media for engagement.

5. Contact Us (contact.html)

  • Purpose: To provide a means for users to get in touch with the studio.
  • Audience: Potential clients, partners, and community members.
  • Content: Contact information, a message form, and a map showing the studio location (simulated).
  • Data Entry: Yes; a contact form for users to submit inquiries.
  • Validations: Required field checks for name and message; email format validation.
  • Interactions: Input fields, submit button, and an interactive embedded map.
  • Actions: Clicking submit validates and processes the form data, showing a success message; map allows panning and zooming.
  • Special Notes: None.

Dynamic Functionality

  • Image Slider (Home Page - index.html):
    • Description: An interactive carousel that cycles through high-resolution screenshots of Roblox game environments.
    • Why: To capture user interest immediately upon landing and showcase visual quality without overwhelming the page with vertical content.
    • Example: Steam Games Store Image Carousel
  • AJAX Component (Projects Gallery - projects.html):
    • Description: A dynamic filtering system that updates the project grid based on category selection without a full page reload.
    • Why: Provides a seamless, "app-like" experience and reduces server load by only fetching necessary data fragments.
    • Example: Steam Search Filtering
  • jQuery-UI Component (About Us - about.html):
    • Description: An accordion layout to organize studio history and hardware specifications into collapsible headers.
    • Why: Helps users navigate dense technical information quickly by allowing them to expand only what is relevant to them.
    • Example: Official jQuery-UI Accordion Demo
  • Scroll-to-Top (Developer Blog - blog.html):
    • Description: A functional navigation aid that appears as users scroll down the page, enabling a smooth transition back to the top.
    • Why: Significantly improves the user experience for long-form content by reducing the effort needed to access the main menu or header.
    • Example: W3Schools Scroll to Top Button
  • Form Validation (Contact Us - contact.html):
    • Description: Real-time JavaScript validation to ensure email formats are correct and required fields are populated before submission.
    • Why: Improves data integrity and prevents user frustration by providing immediate feedback on input errors.
    • Example: W3Schools JavaScript Validation
